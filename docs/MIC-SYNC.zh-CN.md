# PairUp 中文增强版：麦克风自动校准

## 本地新增功能

- 每台输出设备支持 0–3000 毫秒延迟。滑杆用于粗调；下方四个按钮每次减少或增加 1 / 0.1 毫秒，按住可连续调整。也可以直接输入小数（例如 187.1）后按回车。
- 手动延迟使用独立的延迟存储。原程序的播放队列自动微调不会再逐渐抵消这个数值。
- 自动清理持续增加的软件积压，单台输出和多台一起变慢都能处理。按实际播放取声记录最低积压，避免把正常的大批量取声误当成延迟。
- 每台设备显示“软件等待”和“驱动排队”，把鼠标放在这块状态上可查看驱动报告的最大延迟。读取失败显示“未知”。这些系统数据不等于完整的蓝牙声音到达时间。
- “麦克风自动校准”使用独立麦克风，依次测量当前音源和选中的输出音箱；每台测三次。
- 音乐在测量期间暂时静音，结束、失败或取消后恢复。旧延迟在整个测量期间得到保留，只有完整、可靠、可应用的结果才覆盖它。
- 录音只保留在电脑内存中，不保存文件或上传。

## 使用方法

1. 音乐播放器使用当前音源（这台电脑目前是 Joy），在 PairUp 中打开 AUX 和 CM510。这台电脑的 AUX 实际是“耳机（2- Realtek(R) Audio）”，不要选另一项“扬声器（2- Realtek(R) Audio）”。
2. 把“麦克风（KO-STAR M-640）”放在平常听音乐的位置，音箱保持原位置。让环境安静。
3. 在主窗口点击“麦克风自动校准”。默认选中 KO-STAR 麦克风，勾选能被麦克风听到的音箱。因为这台电脑把 AUX 叫作“耳机”，请手动勾选“耳机（2- Realtek(R) Audio）”。
4. 点击“开始自动校准”，等待每台三次测试。测输出时会先响 Joy，再响待测音箱，两声之间故意留出约两秒；总共约一分钟。不要移动麦克风、切换音源或改变音箱音量。
5. 可靠的测量默认会自动应用并保存。窗口显示每台相对音源提前或落后的时间和实际应用的延迟。

耳机默认不参与，必须把耳机放在麦克风旁边才能测量。不要使用蓝牙音箱的通话麦克风，否则可能切换到通话模式。

这是按需测量：移动音箱、重新连接蓝牙或听出不同步时重新运行。没有持续监听麦克风。

## 自动校准怎样工作

程序生成短扫频测试音，把电脑中取得的参考声音和麦克风收到的真实声音对比，查找同一个测试音到达的时间。两条录音使用 Windows 提供的共同时间戳。

测输出音箱时，声音经过 PairUp 平常使用的转发路径，包括转发队列、声卡和蓝牙输出。当前音源保持出声，让会在静音时停转的驱动继续提供参考和转发声音。给待测输出临时加入已知的额外延迟，把它和 Joy 的测试音分开，计算时减去这个已知延迟。三次使用不同间隔，避免把 Joy 的晚回声误认成待测音箱。结束后先恢复原设置，再决定是否应用新数值。

程序先去掉测试音频率范围之外的杂音，再识别测试音。它仍拒绝测试音过小、原始录音明显失真、难以区分的回声、测试音内时间记录不连续、三次测量差距超过 20 毫秒的结果。任意一台不可靠时不会部分修改其它音箱。完整可靠的自动补偿结果保留一位小数。

0.1 毫秒是设置的调整步长，不代表麦克风测量或蓝牙播放能稳定达到这个误差。测量窗口显示三次结果的差距；蓝牙连接状态和房间回声都会影响实际精度。

## 当前限制

当前音源直接播放，PairUp 无法延迟这条直接声音。因此自动校准以当前音源为基准，只能给比它快的输出增加延迟。若有一台输出比音源更慢，程序保留旧延迟并说明原因。要给所有实体音箱补偿，需要一个不会发声的音源，再把所有实体音箱作为转发输出。

无法可靠取得时间记录、麦克风没有收到清楚的测试音，或音源自身延迟超过当前能安全分开测试音的范围时，程序停止并保留旧延迟。3000 毫秒是补偿范围；蓝牙延迟会随连接和设备状态变化，不能保证一次测量永久有效。

Windows 报告的“最大延迟”在同一条播放声音流的使用期间是固定值。“驱动排队”可读取当前等待播放的数据量，但不一定包含蓝牙音箱内部的所有缓存。这些数据用于观察系统排队，软件会自动限制自己的积压；仍需麦克风或试听确认音箱真实同步。

原来的点击听音估算仍可使用，提示音间隔已改为 8 秒，以容纳最长 3000 毫秒延迟。这种估算包含人的反应时间，推荐使用麦克风校准。

## 开源参考和许可

- 原程序：[PairUp](https://github.com/jamimmehdi/pair-up-audio)，MIT，保留原 LICENSE。
- Windows 声学校准实现参考：[Resonalyze](https://github.com/DIMOSUS/Resonalyze)。参考其“参考声音与收音声音对比”的方法；本增强版的扫频、归一化相关和延迟存储独立实现，没有引入该项目的代码或整套依赖。
- Windows 时间戳定义：[微软 IAudioCaptureClient.GetBuffer 文档](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer)。声音包的 QPC 值单位为 100 纳秒。
- 系统延迟的定义：[微软 IAudioClient.GetStreamLatency 文档](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-getstreamlatency)。该值是最大延迟，在同一声音流使用期间保持固定。
- NAudio 2.2.1、QRCoder 1.6.0 使用原项目已有依赖。

增强版不是上游官方发行版。将来安装上游原版更新可能覆盖本地新增功能。

## 检查边界

`tools/SyncChecks` 检查了实际延迟存储、自动微调策略、立体声、信号识别、录音断流拒绝、完整结果应用策略及配置写入失败保留旧文件。它不打开实体音箱，不能代替在这台电脑的麦克风测量或用户实际试听。

实际验证记录见输出目录的“自动校准检查结果.txt”。单次 Joy 测试音的参考和麦克风识别已在这台电脑上通过，但这不等于 Joy、AUX、CM510 的完整三次测量都已成功。更新时保留用户关闭程序前的最新手动数值，校准不完整时继续保留。
